## What was built

## Evidence for key choices

- **OLLAMA_NUM_CTX = 16384.**
  - Ollama v0.40 docs: the default context is 4096 below 24 GiB VRAM (`docs/context-length.mdx`, FAQ).
  - The Ollama library lists `gemma4:e4b` at 128K context, with text and image input.
  - This machine has no discrete GPU and 15.3 GB RAM. 16k fits typical PR diffs at a sane memory cost, and the adapter refuses anything larger instead of truncating.
- **Ollama features confirmed from the v0.40 API docs:**
  - `format` accepts a JSON schema;
  - `images` take base64 strings on the message;
  - `think` accepts a bool or a level, and `/api/show` returns a `thinking.values`/`default` object;
  - `keep_alive` takes a duration string or seconds;
  - `options.num_ctx`, `seed`, `temperature` and `num_predict`;
  - responses carry `prompt_eval_count`, `eval_count` and `done_reason`.
- **How the driver uses `think`:** it sends `think` only when `/api/show` reports thinking support, and sends `false` only when `values` contains `false`.
- **Gemini/Gemma, confirmed from Google's "Gemma on the Gemini API" docs:**
  - model ids `gemma-4-31b-it` and `gemma-4-26b-a4b-it`;
  - system instructions;
  - image input;
  - thinking toggled by `thinking_level` (`high` on, `minimal` off).
- **Gemini/Gemma, not confirmed:** native structured output (`response_json_schema`) for Gemma. It is requested anyway and always validated.
- **SDK details:** checked against google-genai 2.33 source. It uses httpx and does no retries by default; our adapter retries. `GenerateContentConfig` has `response_json_schema`, `seed` and `thinking_config`.

## Decisions and deviations

- `ModelAdapter` is the `ModelBackend`. The Ollama, Gemini and fake classes are drivers wrapped by it, so the core behaviour exists once. `get_backend()` returns the adapter.
- `FakeBackend` landed in the adapter-core commit (Part 3), because the core's tests need it.
- The adapter also records an `error` audit event when a call fails, and refuses calls with no run unless `allow_unaudited=True` is passed. Policy blocks raise `PolicyViolation`.
- The gemini dependency is a project **extra** (`uv sync --extra gemini`). `make setup` and CI install all extras so the Gemini driver is tested.
- `make model-check` makes its two calls in one run; the second must be a cache hit. Exit codes:
  - 2 for a configuration problem;
  - 1 for a backend or model problem;
  - 3 when the vision check fails.
- I also fixed the P01 `.PHONY` line in the Makefile, which contained a literal `\n`.
