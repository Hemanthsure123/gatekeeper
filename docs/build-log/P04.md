## Decisions and deviations

- **REVIEW_DIFF_TOKEN_BUDGET default = OLLAMA_NUM_CTX − REVIEW_MAX_OUTPUT_TOKENS − 2,048**, which is **13,536** with the defaults (16,384 − 800 − 2,048).
  - The 2,048 reserve covers the system text, the JSON schema, the template and the signal summary, which together measure about 1,235 tokens in the adapter's own conservative estimate. A test keeps that under the reserve.
  - The intake step also subtracts the title and body estimate per item.
  - Everything uses the adapter's 3-bytes-per-token estimate, so the adapter's pre-check won't reject a prompt the budget accepted.
- **Scrub scope:** beyond the title, body and patches, paths, labels and check names also lose the login, because otherwise the leak guard would block legitimate reviews.
  - Login matching treats `-` and `_` as separators, so `from-<login>` is caught.
- **Email-regex fix:** the email pattern in `redaction.py` and `scrub.py` now requires an alphanumeric first character. `+@pytest.fixture` in a diff was being masked as an e-mail.
- **Leak-guard trips fail the run:** PolicyViolation from the guard makes the analysis `failed`, not abstained (fail closed). The scrub should make this impossible; if it happens, it's a bug to look at.
- **Abstain reasons:** `too_large`, `model_output_invalid`, `input_too_large`, `truncated_input`, `low_confidence` and `negative_needs_more_confidence`. Plain `needs_human_look` verdicts that pass the thresholds are `completed`.
- **Extra fields in the result:** `rationale`, `model_verdict`, `downgrade_reason`, `citation_validity`, `omitted_files`, `latency_ms` and `cache_hit`.
- **Shared test data:** `backend/tests` is on pytest's `pythonpath`, so tests share synthetic data builders (`factories.py`).

## Limits (by design, for later prompts)

- The scrub does not catch real names, nicknames, other people's handles in patches, or identity inside image URLs. Image URLs stay in the content and are unused.
- Confidence v1 is uncalibrated. The thresholds are policy choices until the eval prompt fits them.
- The banned-word filter is lexical and over-blocks words like "bot" in a legitimate context, falling back to a neutral note.
