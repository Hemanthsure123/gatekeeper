## Decisions

- **D1 Python 3.13.15** is pinned in `.python-version`, with `requires-python = ">=3.13"`. 3.13 is mature, has wheels across the ecosystem and is what CI tests. I didn't claim `>=3.11` support because nothing tests 3.11 or 3.12.
- **D2 Packaging:** the `uv_build` backend, with `module-root = "backend/src"` so `gatekeeper` installs editable and the smoke test checks the installed metadata. The `uv_build>=0.12.5,<0.13` range follows the uv 0.12.5 docs.
- **D3 Secret scanner: gitleaks** v8.30.1 (released 2026-03-21, actively maintained). detect-secrets was rejected because its last release is 1.5.0 from 2024-05-06. Locally it runs through the pre-commit `golang` hook (pre-commit bootstraps Go). CI downloads the release binary, verifies its SHA-256 and scans the full git history. It doesn't use `gitleaks-action`, because that requires a paid license for organization accounts.
- **D4 Non-default host ports (15432/16379)** prevent clashes with other local Postgres/Redis instances. Both bind to `127.0.0.1` only. `DATABASE_URL` and `REDIS_URL` use `127.0.0.1` to avoid IPv6 `localhost` resolution against an IPv4-only bind.
- **D5 `DATABASE_URL` counts as a secret** because it embeds the password. It stays empty in `.env.example` and `make init-env` builds it. The scheme is plain `postgresql://`, and the driver suffix is left to the persistence prompt.
- **D6 init-env semantics:** it creates `.env` with `O_CREAT|O_EXCL` and mode 0600, so it never overwrites, even in a race. Every key it doesn't manage is written empty, even if the template gains a default later. Output lists key names only. A second run exits 1 with a message.
- **D7 doctor** reads `OLLAMA_BASE_URL` from the process environment only, falling back to `http://localhost:11434`. It never opens `.env`, strips `user:pass@` before printing URLs, accepts only `http(s)` schemes, and always exits 0. It also checks the Docker daemon and Compose, beyond the requested git, python, uv, docker and ollama.
- **D8 Tests beyond the single smoke test:** `scripts/tests/` covers init-env and doctor. These scripts handle secrets, and CLAUDE.md requires every module to ship with tests. Coverage is 92%, against a gate of 85%.
- **D9 CI:** actions are pinned to full commit SHAs with version comments (`actions/checkout` v7.0.1, `astral-sh/setup-uv` v10.3.2). Permissions are `{}` at the workflow level and `contents: read` per job. `persist-credentials: false` is set. The uv version is pinned to 0.12.5 to match the lockfile author. CI runs the same `make` targets as local work, plus the pre-commit file-hygiene hooks.
- **D10 Dependabot** covers `uv` and `github-actions`, weekly, with a 7-day cooldown that zizmor recommended for supply-chain safety.
- **D11 LICENSE:** the official Apache-2.0 text from apache.org (SHA-256 `cfc7749b…3d30` before editing). The only change is the appendix holder field, `[name of copyright owner]` → `<YOUR NAME OR ORG>`. `[yyyy]` is untouched.
- **D12 Makefile recipes are shell-agnostic.** They were tested under Git Bash `sh` and under `cmd.exe` (make started from PowerShell). `clean` uses an inline Python snippet and never touches `.venv`, `.env` or Docker volumes.
- **D13 Extra hygiene files and hooks:** `.gitattributes`, plus `check-toml`, `check-json`, `check-merge-conflict`, `mixed-line-ending` and `detect-private-key`.

## Claude Code permissions

`.claude/settings.json` denies `Read(.env)`, `Read(secrets/**)` and `Read(*.pem)`. The syntax was confirmed against the current docs at `code.claude.com/docs/en/permissions.md` and `settings.md`. Read rules use gitignore patterns. A bare name matches at any depth. A `dir/**` deny rule matches that directory at any depth. `*.env`-style globs are documented as matching at any depth. A Read deny also blocks Edit and Write on those paths. The file validates against the schemastore `claude-code-settings.json` schema. `.env.example` stays readable on purpose.

**Limitation (from those docs):** deny rules cover Claude's file tools and recognized shell readers such as `cat` and `head`. They don't cover arbitrary subprocesses, such as a Python script that opens the file. OS-level enforcement needs the Claude Code sandbox.
