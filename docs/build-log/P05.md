- **Scope:** P04 follow-ups, `make env-set`, the Gemini key pool, gemma-setup, the private-repo guard, GitHub account commands, the demo pack, docs and the live run. There are no GitHub write calls, and Ollama is kept.

## What was built

- **P04 follow-ups:**
  - The banned-word filter applies only to the model's contributor note.
  - A leak-guard trip fails the analysis with `identity_leak_blocked` (not retryable; visible in `gatekeeper jobs`).
  - `typo_scale` is neutral.
  - `make doctor` reports Ollama as *info* when another backend is active. It reads exactly one non-secret key, MODEL_BACKEND, from `.env`.
  - Doctor tests no longer wait about 2 s on a closed port.
- **Test durations:** the slowest items are per-session database setup and teardown (about 3–3.7 s, shown against the first and last tests) and the migration round trip (2.4 s). No test sleeps or uses the network. The 28-minute run in P04 was the machine; reruns take 26–36 s.
- **`make env-set`** (`gatekeeper/envfile.py`, `scripts/env_set.py`):
  - It sets allowlisted, non-secret keys only, with explicit exceptions for names that merely contain KEY, TOKEN or PRIVATE.
  - Refusals change nothing. Other lines are preserved, values are never printed, and `.env` is never created.
- **Key pool** (`gatekeeper/models/key_pool.py`):
  - The Gemini driver fails over inside the adapter, so audit, cache, retries and validation are unchanged.
  - `backend_meta` in `model_response` records the alias and the failover count.
  - The Redactor masks every pool key plus the `AIza…` shape.
  - Logs keep numbers and `key-N` aliases readable (previously `input_tokens` and `key_alias` were masked because their names contain "token" or "key").
- **gemma-setup** (`gatekeeper/models/gemma_setup.py`, `make gemma-setup`):
  - It prints a per-alias table, picks the 26b-a4b and 31b models from the models endpoint, and sets MODEL_BACKEND, GEMMA_MODEL_PRIMARY and GEMMA_MODEL_SECONDARY.
- **Private-repo guard:** a private repository on `gemini_api` becomes a failed analysis with `private_repo_hosted_model_blocked`.
- **Context limits:** Gemini reads `input_token_limit` from `models.get` (262,144 for gemma-4-26b-a4b-it), falling back to 131,072.
- **GitHub account commands:** `gatekeeper whoami`, `discover-repo` and `list-prs`.
  - New read-only client methods: `/user`, `/rate_limit` (`resources.core`), `/user/repos` and `/repos/{o}/{r}/pulls?state=open`.
  - The access check is a cheap read of `/pulls` and `/issues`.
- **Demo pack:** `demo/` contains the base `textkit` package with one real `truncate` bug, issue #1, five PRs, `expected.md`, `seed.ps1` and `seed.sh`, and a README. A structural test proves the base has the bug and that PR 1 fixes it.

## Decisions and deviations

- **Redis-shared cooldowns (optional): not done.** Cooldown state is per process, which is enough for one worker.
- **Google key format:** Google publishes no formal spec. I used the widely used shape from gitleaks' `gcp-api-key` rule: `AIza` followed by 35 URL-safe characters.
- **Invalid-key detection:** 401, 403, or a 400 whose body names `API_KEY_INVALID` or "API key not valid", per the Gemini API errors page. A 403 can also mean the project is restricted; the key is still treated as dead for the process.
- **`whoami` in App mode** prints a short note, because installation tokens have no user. Account checks need the personal token.
- **SDK fix:** `gemma-setup` keeps a reference to the SDK client while listing models. A temporary client was being garbage-collected and closed its HTTP connection mid-iteration.
- **Demo linting:** the demo pack is excluded from ruff, and `demo/prs/2-whitespace-noise/` is excluded from pre-commit, because that PR is noisy on purpose.
