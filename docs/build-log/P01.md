# Build log: P01, backend foundation

- **Date:** 2026-10-25
- **Scope:** settings, logging, errors, env tooling, database schema and migrations, and the audit trail. There are no endpoints, model code, GitHub code or workers.

## What was built

- **Housekeeping:** uv was upgraded to 0.13.5, with the CI pin, `required-version` and the `uv_build` range moved to match. Dependabot now also watches `docker-compose`. The `.env.example` prompt numbers were updated, and CLAUDE.md gained the new working rules and the extension design principles.
- **`gatekeeper.config`:**
  - pydantic-settings, with every `.env.example` key typed and secrets as `SecretStr`;
  - empty values mean unset, and unknown variables are ignored;
  - URL, port, log-level and positive-ID validation;
  - `hide_input_in_errors` plus a `ConfigError` wrapper that names keys, never values;
  - `require()` and a cached `get_settings()`.
- **`gatekeeper.logging`:**
  - structlog over stdlib with one `ProcessorFormatter` pipeline, so third-party logs are redacted too;
  - JSON output outside development and console output in development;
  - ISO-8601 UTC timestamps and contextvars binding;
  - key-based masking, the shared `Redactor`, and request/response bodies omitted by default.
- **`gatekeeper.errors`:** stable codes, with `to_public_dict()` returning only code, message and retryable.
- **`gatekeeper.redaction.Redactor`:** shared by logging and audit, and re-exported from `gatekeeper.audit`.
- **`make env-check` / `make env-sync`** via `scripts/env_tools.py`.
- **`gatekeeper.db`:** models, `sqlalchemy_url()`, `create_db_engine()`, `create_session_factory()` and `session_scope()`. Alembic revision `0001` creates the four tables, `events`, and the append-only trigger. Make targets: `migrate`, `migrate-down` and `db-reset` (`scripts/db_reset.py`).
- **`gatekeeper.audit`:** `AuditRecorder`, `Run`, `AuditReader` (`get_events`, `verify_chain`), `verify_events`, canonical hashing, and the `EventType`/`Actor` enums.
- **Tests:** unit tests per module, plus `integration`-marked database tests that run in throwaway `gatekeeper_test_*` databases. CI has a Postgres service, and the tests fail there instead of skipping. `make check` was added.

## Decisions and deviations

- Commit order follows dependencies, not part numbers: errors (Part 3) landed before settings (Part 1), because `require()` raises `ConfigError`.
- The `Redactor` lives in `gatekeeper/redaction.py`, which logging (Part 2) needs first. It is re-exported from `gatekeeper.audit` as the spec places it.
- There is no separate `run_id` index on `events`, because the unique `(run_id, seq)` index already serves those lookups. `item_id` is indexed.
- Additions beyond the spec:
  - the trigger also rejects `TRUNCATE`;
  - the item content identity guard (ORM check at any depth, DB `CHECK` at the top level);
  - `CHECK` constraints for seq, parent_seq ordering, actor, kind, status and confidence;
  - `hide_parameters` on engines;
  - a migration/model drift test.
- `db-reset` runs **only** when `APP_ENV=development`. That is stricter than "refuse in production" and matches "development only".
- `pydantic` is used directly (`SecretStr`, validators). It arrives as a dependency of pydantic-settings and isn't listed separately.
- CI Postgres uses trust auth with no password, so no credential appears in the workflow.
- The test-only Ruff ignores `S105`/`S106` allow obviously fake credentials in tests. Fake tokens are built at runtime with low entropy so gitleaks stays quiet.
