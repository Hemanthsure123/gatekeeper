## Verified from docs, or live

- **Chrome side panel:**
  - `side_panel.default_path`, the `sidePanel` permission (Chrome 114+), `sidePanel.open()` (Chrome 116+);
  - `setPanelBehavior({ openPanelOnActionClick: true })`, which needs the `action` key.
- **Manifest V3:**
  - match patterns may name a port (`http://127.0.0.1:8000/*`);
  - a module service worker uses `"type": "module"`; `options_ui` with `open_in_tab`;
  - content scripts run at `document_idle` by default;
  - the default extension CSP is `script-src 'self'` (no remote code).
- **Extension network:** extension pages with host permissions may fetch cross-origin. Content scripts may not, so every API call is made from the panel. No CORS middleware was added.
- **Tabs and messaging:**
  - `tabs.query`, `tabs.update` and `tabs.sendMessage` behave as documented;
  - the `tabs` permission, or host permissions, expose `tab.url`;
  - asynchronous replies still use `return true`; returning a promise only arrives in Chrome 148 and is rolling out gradually.
- **GitHub "Files changed":**
  - the current experience uses `/pull/N/changes` and has been the default since 2026-01-22;
  - existing `/files` URLs keep working and redirect, so the extension navigates to `/files` and accepts both routes.
- **GitHub REST:**
  - "Get a tree" with `recursive=1` is limited to 100,000 entries or 7 MB and reports `truncated`. It needs Contents: read.
  - "Create an issue comment" is `POST /repos/{owner}/{repo}/issues/{issue_number}/comments` and returns 201 with `id` and `html_url`. It works for PRs. It needs Issues (write) **or** Pull requests (write), and content-creating requests have secondary rate limits.
  - **Live check:** the tree endpoint accepts a **commit** SHA. A read-only call on a public repository returned 200 with entries. The docs only say "SHA1 or ref".
- **FastAPI SSE:** FastAPI 0.135+ ships `fastapi.sse` (`EventSourceResponse`, `format_sse_event`). The installed 0.162 source shows a 15 s automatic keep-alive. The stream uses `EventSourceResponse` with our own async byte generator, so that 404 and 403 are raised before streaming starts and heartbeats come every 10 s.
- **EventSource** has no option for custom headers, so the panel reads SSE with fetch streaming.
- **Gemma licensing:**
  - Gemma 4 is released under Apache 2.0 (`ai.google.dev/gemma/apache_2`, linked from the Gemma Terms page);
  - the Gemma Terms of Use and the Prohibited Use Policy cover the earlier Gemma models;
  - the README links all three.

## Decisions and deviations

- **The diff anchor is not documented.** `#diff-` plus the SHA-256 of the path, with `R<n>` for new-side lines, comes only from community sources. So the content script tries, in order:
  1. that id;
  2. path data attributes;
  3. anchor links;
  4. header text.

  The background script then sets the anchor in the URL, and as a last resort opens the file's blob page at the PR's commit (the base commit for removed files).
- **The PR context is sticky.** The panel keeps the PR open while the tab browses other pages of the same repository, such as a folder or file opened from the tree. Otherwise a folder click would replace the review.
- **Keyboard and tree navigation:** arrow keys expand and collapse folders without navigating GitHub. A click, or Enter, navigates when "Follow clicks" is on. "Open in GitHub" and evidence links always navigate.
- **Pending analyses:**
  - "Analyse" and "Re-analyse" create a pending analysis when the PR is already stored, so the panel can stream from the first event.
  - A never-seen PR has no item row yet, so the panel polls `/api/pr` until the run appears.
  - A pending analysis whose job fails before the run starts is marked failed, with `run_failed`.
- **`emit` is a method,** `ActivityFeed.emit(analysis_id, kind, ...)`, rather than a module-level function, because it needs a session factory and a redactor. A no-op `NullActivity` keeps existing callers and tests working.
- **Per-file signals** come from a new display-only function, `review_core.signals.file_signals`, because the PR-level signals carry almost no per-file evidence. They are stored in the result as `file_signals`.
- **HTTP statuses:**
  - `config_error` now maps to 503 (the API without `GATEKEEPER_ADMIN_TOKEN`);
  - model errors map to 413, 502, 503 and 504;
  - the identity and private-repository blocks map to 403;
  - request validation errors return the error model's shape with 400 instead of FastAPI's 422.
- **New error code** `github_write_forbidden` (403). It names the permissions needed, never a token value.
- **Dependency versions** were pinned exactly and are at least 16 days old: vite 8.3.4, @types/chrome 0.3.5, typescript 7.0.2. vite 8.3.5 and @types/chrome 0.3.6 were only 4 days old.
- **Chart colours:** chart marks use `#3b5bdb` in light mode and `#6c84f0` in dark mode. Both passed the dataviz palette checks; the UI accent `#91a7ff` failed the dark-mode lightness band for chart marks.
- **Commit message:** PowerShell 5.1 stripped the double quotes from one commit message (Part 3: `live Now line`). Later commits use `git commit -F`.

## Fixes after the first live use

- **Missing Checks permission:** a token without Checks: read gets 403 on `check-runs`. That failed every job before an analysis existed, and the panel waited forever. Check runs are now optional (warning, no CI signal). The panel also polls `GET /api/jobs/{id}` and shows why a job failed.
- **Private repositories:** these are blocked on the hosted model, and the global switch is too broad. I added per-repository, audited, revocable consent, granted from the panel; see the ADR 0006 amendment. Claude Code's safety check refused to flip the global switch on the user's behalf. That is correct: consent is the user's decision.
- **Hidden elements:** a global `[hidden] { display: none !important }` fixes elements that author `display` rules kept visible.
