# Build log: P03, GitHub client, webhook gateway, job queue, pipeline skeleton

- **Date:** 2026-10-25
- **Scope:** an event flows end to end into a completed, audited stub analysis. There is no review logic, no model calls in the pipeline and no GitHub writes.

## What was built

- **Part 0:**
  - `make model-check` now prints a WARNING and exits 0 when only vision fails; `--require-vision` makes that exit 3.
  - The adapter logs `estimated_input_tokens` next to the reported `input_tokens`, and ADR 0003 has the calibration note.
  - Nine new optional settings: GATEKEEPER_ALLOWED_REPOS (case-insensitive), GITHUB_API_BASE_URL, WEBHOOK_MAX_BODY_BYTES, JOB_TIMEOUT_S, WORKER_POLL_INTERVAL_S, JOB_LEASE_S, JOB_MAX_ATTEMPTS, DIFF_MAX_BYTES and PR_MAX_FILES. `make env-sync` appended them to `.env` with empty values.
- **Part 1, `gatekeeper.github`:**
  - `auth.py` handles token and App modes, with lazy resolution.
  - `client.py` is read-only, with pagination, rate limits and retries.
  - `models.py` holds the typed response models.
- **Part 2, `github/normalize.py`:** `ItemContent` vs `AuthorInfo`, flags for missing and omitted patches and binary files, truncation reasons, closing-keyword references, image URLs, and `content_hash`.
- **Part 3, `gatekeeper.api`:** a FastAPI app factory with request-ID middleware, `/healthz`, `/readyz` and `/webhooks/github`. Run it with `make api` (`python -m gatekeeper.api`, bound to 127.0.0.1:8000).
- **Part 4:**
  - Migration `0003` adds `webhook_deliveries` and `jobs`.
  - `gatekeeper.queue` provides `enqueue`, `JobQueue` and `Worker`.
  - `api/store.py` holds the Postgres delivery store.
  - Run a worker with `make worker` (`python -m gatekeeper.worker`).
- **Part 5:**
  - `gatekeeper.pipeline` provides `ItemView`, `PipelineContext`, `Step`, `Pipeline`, the stub steps and `process_pr`.
  - `gatekeeper.identity` is the only code that touches `item_authors`.
  - `gatekeeper.review_core` is an empty package guarded by the AST test.
- **Part 6:**
  - The `gatekeeper` console script has `fetch-pr`, `enqueue-pr`, `audit` and `jobs`.
  - `make relay` runs `scripts/relay.py`, which calls `npx --yes smee-client@5.0.0 --url … --target …`.
- **Part 7:** tests, ADR 0004 and this log.

## Decisions and deviations

- **Commit order.** Migration 0003 and the Postgres delivery store landed with the queue (Part 4), because the store needs `enqueue`. The gateway (Part 3) depends only on a `WebhookStore` protocol and was tested with an in-memory store.
- **Worker entry point.** `gatekeeper/worker.py` wires the worker to `process_pr`, so the queue package never imports the pipeline.
- **New error codes:** `authentication_failed` (401), `payload_too_large` (413) and `job_timeout`.
- **Audit run id.** `AuditRecorder.start_run` takes an optional `run_id`, so the analysis row and the audit run share one id.
- **Stub audit events.** The review step records the `verdict` event (`{"stub": true}`), and decision records `decision`. `run_end` closes the run, and the analysis becomes `completed` with result `{"stub": true}`. The intake event records `head_sha` and `content_hash`, because `analyses` has no head column.
- **Account age is advisory.** If `GET /user/{id}` fails, `account_created_at` is stored as null and the run continues.
- **Redundant allowlist checks.** The allowlist is enforced in the gateway, again in `process_pr` (PolicyViolation), and in the CLI.
- **Gateway tests use `httpx.ASGITransport`.** Starlette 1.10's `TestClient` now raises a deprecation that asks for the separate `httpx2` package, which isn't an allowed dependency.
- **CLI exit codes:** 1 for allowlist refusals and failures, 2 for usage or config errors.
- **Login scrubbing deferred.** Removing the author's login from free text (title, body, patches) is **not** done here; the intake step in a later prompt will do it.
- **`is_first_contribution`.** It is true for `FIRST_TIME_CONTRIBUTOR` or `FIRST_TIMER`, taken from the PR's `author_association`.
  - GitHub computes this per repository at event time.
  - `FIRST_TIMER` means a first contribution anywhere on GitHub.
  - A deleted or ghost account reports `NONE`.

## Not tried live

- **Real GitHub calls.** These are untested in both token mode and App mode. App mode (JWT, installation lookup, token caching) is covered only by respx tests with a throwaway RSA key.
- **`make relay`.** smee-client 5.0.0 has never been run here. Its flags come from its `bin/smee.js` help text.
- **`make api` and `make worker`** as long-running processes. Ctrl+C behaviour on Windows was only tested through `request_stop()`.
- **The real end-to-end path** (Gate 0, against the playground repo) is still to come.
